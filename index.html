02 / REFERENZPROJEKT

Mentat

Ein Multi-Agenten-System, in dem autonome KI-Agenten sich evolutionär weiterentwickeln: mit Mutation, Selektion und validierten Lessons, die zwischen den Generationen weitergegeben werden. Ein privates Forschungsprojekt, das bewusst nur im Simulationsmodus läuft.

Meine Rolle, ganz transparent: Den Produktionscode schreiben KI-Coding-Agents. Ich habe das System entworfen, das sie kontrolliert: Spezifikation in 16 Modulen, 31 dokumentierte Architekturentscheidungen, testgetriebene Abnahme jedes Arbeitspakets mit eigenen Mutationstests, dazu der Betrieb der Sandbox-Infrastruktur. Genau das biete ich an: KI-orchestrierte Entwicklung mit echter Qualitätskontrolle.

Kalibrierungs-Gate für KI-Urteile

Ein Sprachmodell darf erst bewerten, wenn es 100 vorab beurteilte Fälle mit mindestens 80 Prozent Übereinstimmung besteht, dazu eine Diagonalprüfung gegen Immer-gleich-Antworten. Zwei Golden-Sets sind durchgefallen, die Schranke blieb trotzdem stehen. Bestanden hat erst das dritte, mit 97 von 100.

Prompt-Injection strukturell unmöglich

Web-Inhalte erreichen die Agenten als Datentyp, der schlicht keinen Weg in einen Prompt hat: keine String-Konvertierung, ein einziger Ausgang, alles als untrusted markiert. Belegt per Byte-Prüfung des gesamten Requests. Keine Regel, die man umgehen kann, sondern Konstruktion.

Sandbox, die Ausbrüche wirklich hält

Agenten-Code läuft in gVisor auf einem eigenen Linux-Host, 19 dokumentierte Ausbruchsversuche wurden abgewehrt. Zweimal hat die Test-Suite dabei falsche Sicherheit aufgedeckt: grüne Wände, die nie geprüft wurden. Danach wurde das Testdesign selbst gehärtet.

Der Maßstab ist unerreichbar

Fitness-Evaluator und Beweisfunktionen liegen außerhalb der Reichweite der Agenten, durchgesetzt auf Datenbank-Rechte-Ebene statt im Applikationscode. Kein Agent kann seinen eigenen Wert deklarieren. Evidenz kommt nur aus unabhängigen externen Quellen.

Stack: Python 3.12 · uv · Pydantic v2 · FastAPI · PostgreSQL · Alembic · pytest + hypothesis · ruff · mypy --strict · Docker · gVisor · Hetzner (Ubuntu 24.04)

Die vollständige Projektdokumentation (Spezifikation, ADRs, Statusprotokoll) zeige ich gern im Gespräch. Das Repository selbst ist privat.

03 / GEMEINSCHAFTSPROJEKT

Obsidian-Brain-AI & Kanzlei Brain

Ein RAG-System über Markdown-Wissensbasen mit CLI, Web-Oberfläche und MCP-Server. Daraus abgeleitet: Kanzlei Brain, ein eigenständiges B2B-Produkt für Rechtsanwaltskanzleien, erzeugt aus derselben Codebasis über ein deklaratives Preset-System.

Ein Vater-Sohn-Projekt: Idee, Produktvision und Projektleitung liegen bei meinem Vater. Ich habe mitentwickelt und dabei angewendet und vertieft, was auch Mentat trägt: spezifikationsgetriebene, KI-orchestrierte Entwicklung mit Abnahme-Gates, Regressionstests und ehrlicher Qualitätskontrolle.

RAG mit Anti-Halluzinations-Design

Hybrid-Suche aus BM25 und Vektor-Embeddings, Reranking und ein Zitat-Verifikationssystem: Jede Antwort verweist auf klickbare Belegstellen im Quelldokument. Findet das System keinen Beleg, sagt es das, statt etwas zu erfinden.

Vom Werkzeug zum Produkt, ohne Fork

Ein Preset-System erzeugt aus derselben Codebasis ein eigenes Kanzlei-Produkt mit eigener Terminologie, Navigation und Compliance-Logik. Das Ursprungsprodukt bleibt als Golden Master unangetastet, nachgewiesen durch Regressionstests bei jeder Änderung.

Compliance technisch umgesetzt

Mandanten-Kollisionsprüfung nach § 43a BRAO, durchgängige KI-Kennzeichnung, Vier-Augen-Freigabe für Fristen, ein Audit-Log ohne Löschmöglichkeit und ein DSGVO-Löschkonzept. Berufsrecht als Code statt als Fußnote.

Eigener Code-Intelligence-Stack

Ein zweiter Analyse-Pfad für Software-Projekte: AST-Parsing mit tree-sitter, Dependency- und Call-Graphen, Contract-Validation an Modulgrenzen. Das System versteht nicht nur Dokumente, sondern auch Code.

Stack: Python 3.12 · FastAPI · HTMX + SSE · Pydantic v2 · ChromaDB · BM25 · tree-sitter · MCP · Playwright · pytest · mypy --strict
